# Forgeron 2.0

Trois chantiers : un design refait, un agent IA durci, et le coworking entre
le PC de l'atelier et une tablette ou un téléphone.

## 1. Design

| Quoi | Où |
|---|---|
| Jetons (espacements, rayons, durées, typographie, ombres, numéro de version) | `lib/core/theme/forge_tokens.dart` |
| Composants communs (`ForgeCard`, `ForgeButton`, `StatusPill`, `StaggerIn`, `ForgeSkeleton`, `PresenceAvatar`, transition de page) | `lib/core/widgets/forge_ui.dart` |
| Thème Material unique, clair et sombre | `lib/core/theme/app_theme.dart` |
| Palette | `lib/core/theme/forgeron_colors.dart` |

Règles :

- Rajdhani pour l'interface, JetBrains Mono pour les chiffres et le G-code.
- Les animations passent par `FMotion.of(context, …)` : elles s'éteignent
  quand le système demande moins de mouvement.
- Plus de flou d'arrière-plan : les panneaux sont des surfaces pleines.
- La mise en page se décide sur la **largeur**, pas sur la plateforme : une
  tablette en portrait reçoit la colonne unique, en paysage les volets.
- Un écran sans donnée montre un squelette ou « absent », jamais un zéro.

Barre latérale en trois sections : PRODUCTION, SYSTÈME, INTELLIGENCE. Le pied
de la barre affiche l'état réel de la session de coworking.

## 2. Agent IA

Ce qui est garanti par le code, et testé dans `test/ai_hardening_test.dart` :

- **Provenance du G-code** (`lib/core/utils/gcode_provenance.dart`). Un
  `run_gcode_program` dont une ligne de mouvement ne figure ni dans un
  message de l'opérateur ni dans un résultat d'outil est refusé avant la
  demande de confirmation (événement `garde.provenance`). La règle « le
  modèle n'écrit pas de G-code » n'est plus seulement dans le prompt.
- **G-code non vérifié**. Un bloc de code écrit par le modèle dans sa réponse
  est marqué « non vérifié : ne pas usiner tel quel » ; les boutons
  enregistrer et ouvrir disparaissent (`garde.gcode_invente`).
- **Secours Gemini**. Si le serveur local ne répond pas, la bascule vers
  Gemini est possible, mais seulement si l'opérateur l'a activée
  (Paramètres de l'agent ; désactivée par défaut). Chaque bascule est
  journalisée (`ia.bascule`) et annoncée dans la discussion.
- **Pré-vol** (`lib/application/providers/ai_preflight_provider.dart`). En
  haut du panneau Santé du Backoffice : agent, fournisseur, modèle, outils,
  réseau, images, lexique, secours, machine. Chaque ligne en défaut dit où
  aller la corriger.

Ce qui n'est **pas** garanti : la justesse des réponses du modèle. Les tests
ci-dessus tournent avec un modèle simulé ; les deux tests de
`local_ai_agent_live_test.dart` demandent un Ollama réel et durent environ
45 minutes.

## 3. Coworking

Le PC héberge, les autres appareils rejoignent par le réseau local.

- Port 8767, code de liaison à 6 chiffres.
- Protocole version 2 (`ChatRelayProtocol.version`), additif : un client
  version 1 continue de recevoir la discussion.

| Message | Sens | Contenu |
|---|---|---|
| `hello` | invité → PC | version, nom et type d'appareil, code |
| `welcome` | PC → invité | identifiant de l'invité, nom du PC |
| `presence` | PC → tous | liste des participants |
| `workspace` | PC → tous | état machine, cotes, avance, broche, programme, simulateur (au plus toutes les 250 ms) |
| `sim` | invité → PC | `follow`, `stop_follow`, `play`, `pause`, `reset`, `speed` |
| `estop` / `estop_ack` | invité ↔ PC | arrêt d'urgence relayé |

Ce qu'un invité peut faire :

- voir l'état de la machine et l'avancement du programme ;
- parler au même agent IA et confirmer ses actions ;
- piloter le simulateur et le jumeau affichés sur le PC ;
- arrêter d'urgence.

Ce qu'il ne peut pas faire : commander un axe par ce lien.

**Arrêt d'urgence.** Le bouton STOP de l'invité appelle
`RemoteChatClient.stopEverywhere()` : d'abord son propre chemin vers la carte
(`streamingProvider.stopStream()`), puis la demande au PC, qui fait de même.
L'écran dit lequel des deux chemins a abouti. Cela **s'ajoute** à l'arrêt
matériel, cela ne le remplace pas : voir le défaut E-STOP connu, qui se
corrige par un contact en série sur la puissance.

Fichiers : `lib/domain/models/cowork.dart`,
`lib/application/services/chat_relay.dart`,
`lib/presentation/screens/cowork_screen.dart`.

## 4. iPad

Le dépôt n'a pas de cible iOS (`ios/` absent) et un build iOS exige un Mac
avec Xcode. État réel :

- les écrans sont vérifiés aux tailles iPad (820×1180, 1180×820, 1024×1366)
  par le balayage de mise en page et par les captures ;
- le protocole ne dépend pas de la plateforme ;
- aucun essai sur un iPad physique n'a eu lieu.

Pour produire l'application iPad, sur un Mac : `flutter create --platforms=ios .`
puis ajouter dans `Info.plist` l'autorisation de réseau local
(`NSLocalNetworkUsageDescription`), sans laquelle iOS bloque la connexion au
PC. Une tablette Android rejoint la session sans rien de plus.
